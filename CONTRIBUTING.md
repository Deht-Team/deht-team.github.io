# Contributing Guide

Thank you for your interest in contributing to this project!  
This guide explains how to contribute in a clear, safe, and respectful way.

---

## 1. Before You Start
Please make sure you have read and understood the **Code of Conduct**.  
All contributors are expected to follow it to keep this project welcoming and safe.

---

## 2. Ways You Can Contribute
There are many ways to help improve the project:

- Reporting bugs or issues  
- Suggesting new features  
- Improving documentation  
- Adding or updating game entries  
- Enhancing code quality  
- Fixing typos or formatting problems  

Every contribution, big or small, is appreciated.

---

## 3. Reporting Issues
If you find a bug or something that doesn’t work as expected:

1. Check if the issue already exists.  
2. If not, open a new issue and include:
   - A clear description of the problem  
   - Steps to reproduce it  
   - What you expected to happen  
   - Any relevant screenshots or details  

Please keep reports respectful and constructive.

---

## 4. Suggesting Features
If you have an idea for a new feature:

1. Open a feature request issue.  
2. Describe:
   - What the feature is  
   - Why it would be useful  
   - How it might work  

Suggestions are welcome as long as they align with the project’s goals.

---

## 5. Adding or Updating Games
When adding a new game entry to the JSON file:

- Each game must be an object inside the array  
- Required fields:
  - `id` — unique identifier  
  - `name` — the game’s display name  
  - `src` — a safe, valid URL or path to the game  

Example structure:

```json
{
  "id": "example-game",
  "name": "Example Game",
  "src": "https://example.com/game"
}
```

Make sure IDs are unique and names are appropriate.

---

## 6. Making Code Changes
If you want to contribute code:

1. Keep your changes focused and clear.  
2. Write clean, readable code.  
3. Add comments where helpful.  
4. Test your changes before submitting.  
5. Follow the project’s existing style and structure.  

---

## 7. Submitting a Pull Request
When your contribution is ready:

1. Create a pull request with a clear title.  
2. Explain what you changed and why.  
3. Keep the tone respectful and helpful.  
4. Be open to feedback from maintainers.  

Pull requests that follow these guidelines are easier to review and merge.

---

## 8. Respect and Safety
All contributors must:

- Be respectful  
- Communicate clearly  
- Avoid harmful or unsafe behaviour  
- Keep the environment friendly for everyone  

This project is meant to be a positive space for learning and creativity.

---

## 9. Thank You
Your contributions help make this project better for everyone.  
Thank you for taking the time to improve it!
